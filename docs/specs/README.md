# Feature Specifications

Use this directory for larger features whose durable specification would make a GitHub issue too long or difficult to maintain.

A useful spec usually contains:

- problem / desired outcome;
- user-visible behavior;
- acceptance criteria;
- edge cases;
- explicit non-goals;
- product/technical constraints;
- migration or compatibility concerns;
- unresolved questions, if any.

The GitHub issue remains the work item and should link to the relevant spec. Specs describe approved behavior; implementation details belong in code/architecture docs unless they are product constraints.
